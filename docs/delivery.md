# 給客戶的交付說明：合約外規檢查 Prototype

日期：2026-11-18｜版本：GitHub `jaylooloomi/contract-check` main

> 一句話：這是一個「提醒工具」。它幫法務先找出合約裡**可能**有個資法問題的地方，並附上法條原文；**是否違法，一律由法務決定**。

## 1. 現在能用什麼
| 功能 | 狀態 | 證據 |
|---|---|---|
| 個資法 66 條入庫，標明來源、修正日期、抓取時間 | ✅ | `data/law_source.json`、`/api/law` |
| 法條可重新抓取、定期更新：重跑不重複、逐條比對、保留版本歷史、失敗不覆蓋舊資料 | ✅ | `scripts/update_law.py`、`docs/law_update.md`、10 個測試 |
| 每個疑慮保存「當時引用的法條原文＋法規版本」，修法後仍可追溯 | ✅ | `findings.article_snapshot`、`law_version` |
| 文字版與掃描版 PDF（看圖認字 OCR） | ✅ | 驗收 AT2、AT3 |
| 關鍵字比對（規則）＋本機 AI，AI 只能引用資料庫中存在的條號 | ✅ | AT4、AT5、AT7 |
| 檢查狀態明確：AI 未啟動、模型不存在、逾時或部分失敗，都會標示「AI 未完成／部分完成」，不會顯示成「沒有問題」；沒有依據的條款標「待人工確認」 | ✅ | `tests/test_status.py`、E2E 截圖 |
| 4 種審閱畫面（主推：精靈引導）、歷史紀錄、複核紀錄只增不改 | ✅ | E2E 測試 |
| 安裝與驗收可重做：套件清單、環境檢查、一鍵驗收腳本 | ✅ | `docs/SETUP.md`、`docs/handoff_verification.md` |

## 2. 準確度：目前能說什麼、不能說什麼
- **新盲測（10 題，修正前就鎖定）：** 只用規則找到 6/10、零誤報；加上 AI 找到 10/10，但合規條款被誤報 10 次。詳見 `eval/report_v2.md`。
- **不能說的：**
  - 這**不是法律準確率**。樣本只有 22 題，答案卷是 AI 寫的，沒有經過法務覆核。
  - AI 的「全部找到」裡有一部分是一次報很多條號碰巧命中。

## 3. 尚未完成
| 項目 | 原因 | 影響 |
|---|---|---|
| 合約資料加密、保存期限、自動刪除 | Prototype 只用虛構合約 | **正式上線前必做**（個資法第 27 條安全維護） |
| 帳號、權限、稽核紀錄、正式部署 | 與驗證「找不找得到」無關，先不做 | 目前只適合單機展示 |
| 更多法規（公司法、勞基法…） | 先證明一部可行，架構已預留 | 只檢查個資法 |
| 用意思找法條（向量檢索）、更強的模型 | 2 小時內不夠做 | 換句話說的寫法仍可能漏 |
| 定期排程實際上線 | 已有指令與文件，未在客戶環境設定 | 需要客戶端設定工作排程器 |

## 4. 風險
1. **漏報：** 規則沒涵蓋的寫法會漏掉（例如外洩通知、預先放棄權利、拒絕行銷）。→ 所以每份合約都要人工複核，並留意「待人工確認」。
2. **誤報：** AI 對合規條款也會提出疑慮。→ 法務可以駁回並留下理由，這些紀錄可以回頭用來修正規則。
3. **法條網頁改版：** 抓取方式依賴網頁結構。→ 更新流程有驗證關卡，失敗時不會覆蓋舊資料，並回傳錯誤碼與寫入紀錄。
4. **資料外洩：** 目前資料庫沒有加密。→ 不要放真實合約，直到第 3 節的必做項目完成。
5. **交接驗證：** 這次是由 AI 代理在乾淨環境中照文件重做，**還沒有由人類工程師在另一台電腦上驗證**。

## 5. 下一階段（依優先順序）
1. **法務覆核答案卷：** 請法務提供 20 份以上去識別化的合約並標註答案；用法務版答案重新量測漏報與誤報，並說明樣本數。
2. **資安必做：** 加密、保存期限、自動刪除、權限與稽核紀錄。
3. **降低誤報：** 限制 AI 每個條款報的條號數，換用更強的模型，用同一份鎖定的盲測卷比較。
4. **補規則與檢索：** 依法務的駁回、確認紀錄補規則，加上用意思找法條。
5. **定期更新上線：** 每週自動重新抓取法條，失敗時通知。
6. **擴充法規範圍。**
