# 合約外規檢查：三種介面版本與 UX 設計說明

使用者是**法務人員**。他們的工作是複核系統標出的「可能疑慮」，判斷要不要寫進審閱意見，而不是看系統替他們下結論。三個版本用的是同一組 API，差別只在複核流程怎麼安排。三版都支援用 `?id=<合約編號>` 直接開啟已檢查過的合約，頁首有 A／B／C 切換列。

## 版本 A：分割檢視（`/`）

| 項目 | 內容 |
|---|---|
| 適用情境 | 條款少（10 條內）的合約，想同時看到全部條款和全部疑慮 |
| 設計重點 | 左邊列條款、右邊列疑慮；點條款可篩選相關疑慮；疑慮旁直接附法條原文 |
| 限制 | 疑慮一多就要上下捲動，不容易看出還剩幾筆沒處理 |

## 版本 B：審閱工作佇列（`/v/b`）

| 項目 | 內容 |
|---|---|
| 適用情境 | 一次要處理很多份合約或很多筆疑慮，重點是快速把每一筆處理完 |
| 設計重點 | 上方固定的摘要列（風險數、待複核／已確認／已駁回、進度條）；一次只顯示一筆；鍵盤 J/K/Y/N；可依來源與狀態篩選；駁回時可填理由；全部處理完會顯示完成狀態；可匯出 CSV |
| 限制 | 一次只看得到一個條款，看不到上下文，比較難發現條款之間的關係 |

## 版本 C：合約全文標註（`/v/c`）

| 項目 | 內容 |
|---|---|
| 適用情境 | 第一次讀某份合約，或要跟業務或對方討論條文時，習慣從頭讀到尾 |
| 設計重點 | 用接近紙本的版面顯示整份合約，有疑慮的條款直接上色（藍＝規則，綠＝AI，橘＝兩者都標出）；點標註會從右側打開抽屜，裡面有疑慮理由、法條原文、確認／駁回按鈕；頁首常駐免責聲明；寬度 800px 以下改成單欄，抽屜改成全螢幕 |
| 限制 | 標註以「整個條款」為單位，還沒做到逐句標註；合約很長時要捲很久 |

## 具體做了哪些 UX 改善，以及原因

1. **法條原文放在疑慮旁邊，不用另外開頁面查**：法務最後一定會回去看條文本身。直接放原文可以省掉切換視窗的時間，也比較不會引用到錯的條號。
2. **標示來源是「規則」還是「AI」**：規則比對的結果可以解釋，AI 的結果可能有誤。標出來源，法務就能決定每一筆要花多少力氣查證，也比較能信任這套工具。C 版直接用顏色區分。
3. **免責聲明一直看得到**：文字寫的是「可能疑慮」，不寫「違法」，避免讓人誤以為系統做了法律判斷。C 版放在頁首、不能收起來。
4. **鍵盤快捷鍵（B 版）**：大量複核時，手不必離開鍵盤。按 N 會直接把游標放進理由欄，按 Enter 送出。
5. **駁回時可以填理由**：理由會一起存起來，之後可以追查「為什麼當時判定沒問題」，也能拿來改進規則和 AI 的誤報。
6. **進度條和待複核數量**：讓人清楚知道還剩多少，B 版全部處理完會明確顯示「全部複核完成」，避免漏掉。
7. **上傳時顯示已等待秒數**：掃描檔 OCR 或 AI 檢查可能要 10–120 秒。顯示秒數並說明大概要多久，比只轉圈圈更不會讓人以為當掉，也不會重複上傳。
8. **錯誤訊息看得懂**：把伺服器回傳的原因（例如「只接受 PDF」、「找不到合約」）直接用中文顯示，並告訴使用者下一步怎麼做。
9. **匯出 CSV（B 版）**：審閱結果可以貼進內部簽核或審閱意見書。檔案加了 BOM，用 Excel 開中文不會變亂碼。
10. **手機版（C 版）**：主管或外勤時可能只用手機快速看一下，所以改成單欄、抽屜全螢幕、按鈕放大。
11. **OCR 提示**：掃描檔會註明「OCR 擷取，可能有辨識誤差」，提醒法務必要時對照原始 PDF。

## 誠實說明與後續驗證

以上設計都是**依照對法務工作的推想做出來的，還沒有找真正的法務使用者測試過**。我目前只確認過：三個頁面都能正常載入、沒有 console 錯誤、手機寬度下不會出現水平捲動，快捷鍵、駁回理由、匯出 CSV 和抽屜複核都能運作。

如果做易用性測試，我會優先驗證：

1. **法務實際偏好哪一種流程**：B（佇列）和 C（全文）哪一種比較快、漏看比較少？可以讓 5 位法務各複核同一份合約，記錄花費時間和漏判數。
2. **來源標示是否真的影響信任與查證行為**：看到「AI」標籤時，使用者會不會比較常去看法條原文？還是根本沒注意到這個標籤？
3. **駁回理由欄會不會有人填**：如果選填時幾乎沒人填，就要考慮改成常用理由的選項（例如「已有當事人同意條款」），降低填寫成本。

## 版本 D：精靈式引導

路徑 `/v/wizard`（A、B、C 未改動，首頁 `/` 仍是 A）。

**改了什麼**
- 把整個流程切成 4 步驟並固定顯示步驟條：① 上傳 → ② 檢查 → ③ 複核 → ④ 完成。每一步畫面只放這一步要做的事。
- ① 大型拖放區（也可點擊選檔），「AI 輔助」改成開關，說明放在 ⓘ 提示。
- ② 顯示已等待秒數與「讀取 → 切條款 → 比對法條」三個階段。**這三個階段是前端依經過時間估計的**，因為後端是一次 API 呼叫，無法回報真實進度；畫面上也有註明。失敗時只顯示一句原因，加「重試」「重新上傳」。
- ③ 一次一張卡片，只列待複核項目；法條原文預設收合；兩顆大按鈕「✓ 是疑慮」「✕ 不是」，鍵盤 Y／N、J／K；按「不是」才展開選填理由。
- ④ 摘要（是疑慮／不是／待複核）、下載報告 CSV（格式同 B 版）、再檢查一份。`?id=` 直接進 ③，全數複核過則進 ④。
- 單一強調色 #2563eb、來源小標籤「規則」「AI」、免責聲明縮成步驟條下一行、支援深色模式、手機寬度不水平捲動。

**為什麼**
- A／B／C 一次把上傳、計數、篩選、卡片全部攤開，第一次使用的人不知道先做什麼；精靈把「下一步」變成唯一選項。
- 按鈕字數少、說明放提示裡，降低畫面雜訊；大按鈕適合手機與快速複核。
- 階段指示誠實標示為估計，避免使用者誤以為是真實進度。

**尚未驗證**：同樣沒有找真正的法務使用者測試；精靈是否比 B 版佇列更快，仍需實測。
